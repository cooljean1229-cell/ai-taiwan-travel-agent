# AI 台灣旅遊情報員 × 智慧行程推薦網站

台灣旅行社的內容獲客與個人化旅遊提案專案。以每週旅遊情報服務親子、情侶及熟齡旅客，再依旅客明確提供的偏好整理合適的旅遊提案。

## 工作計畫

1. **建立規範：**定義事實來源與查詢日期、待確認內容、模擬資料及密鑰保護規則，並訂出角色交接和驗收標準。
2. **建立研究流程：**按客群與主題蒐集可追溯的旅遊資訊，整理成研究素材包。
3. **製作每週情報：**由週報編輯把研究素材轉為可發布內容，保留來源鏈結。
4. **延伸內容：**簡報企劃與影片企劃依核對素材製作不同渠道版本。
5. **建立推薦網站：**網站工程師建置內容展示及偏好導向提案流程；任何示例旅客/推薦資料均標示為模擬資料。
6. **驗收發布：**驗收員逐項檢查來源、日期、標籤、功能、個資與憑證風險；修正後複驗再發布。

角色輸入、產出、交接與詳細驗收標準見 [AGENTS.md](AGENTS.md)。角色是工作分工；若無多 Agent 能力，單一 Agent 依序完成並保留交接紀錄。

## 專案目錄

| 目錄 | 用途 |
| --- | --- |
| `research/` | 旅遊研究紀錄、來源與待確認清單 |
| `weekly-reports/` | 每週情報稿件與渠道短版 |
| `proposals/` | 依旅客偏好整理的提案素材；示例資料需標示模擬資料 |
| `presentation/` | 簡報大綱、投影片素材與講者備註 |
| `video/` | 腳本、分鏡、字幕及素材授權待辦 |
| `website/` | 智慧行程推薦網站程式與設定文件 |
| `acceptance/` | 驗收清單、缺失紀錄與複驗結果 |
| `templates/` | 跨角色共用的研究與交接模板 |

各目錄目前為專案骨架，實際內容尚待建立。不得將空目錄誤認為已交付功能或已完成研究。

## 內容可信度規則

- 外部事實標示來源名稱、頁面標題、網址及查詢日期（YYYY-MM-DD）。
- 未能確認的資訊標示「待確認」，並說明待確認事項。
- 虛構旅客、價格、庫存、評分、成效或推薦範例，必須顯著標示「模擬資料」。
- 不在前端或 Git 放置密碼、API Key、權杖等憑證；敏感設定只從伺服器環境變數讀取。本機 `.env` 不提交，範例設定只使用空值或假值。

## 開始協作

1. 接手者先閱讀 [AGENTS.md](AGENTS.md)。
2. 明確指定本次工作主題、目標客群、週期/有效期間、輸出格式與渠道。
3. 依 `templates/` 建立帶來源及查詢日期的交付物，並將待確認項目留在清單中。
4. 完成後交驗收員檢查，再記錄驗收版本與結果。

目前尚未選定網站框架、資料來源/API、部署平台、個資保存政策及實際商品/價格；上述均為**待確認**，因此本初始化不包含可供客戶使用的推薦功能或即時旅遊資訊。
